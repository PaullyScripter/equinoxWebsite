Privacy Policy

Last updated: July 23, 2026

1. Introduction

Equinox is a multi-purpose Discord bot providing community management, moderation, security, entertainment, automation, and analytics tools.

This Privacy Policy describes what data Equinox collects, how that data is used, where it is stored, and what rights you have regarding your information.

By inviting Equinox to your Discord server or using any of its commands, you agree to the practices described in this policy. If you do not agree, remove the bot from your server and discontinue use.

2. Data We Collect

All data is collected solely to enable bot functionality. No data is ever sold, shared with advertisers, or monetized.

2.1 Server Configuration

  • Guild ID — to associate settings with a specific Discord server.

  • Channel IDs — saved when administrators configure scam detection channels, audit log channels, auto-ping channels, code helper channels, Gemini AI channels, ticket categories, blacklisted message-counter channels, and verification system channels.

  • Role IDs — saved for auto-role, limited roles (join surge protection), scam whitelist roles, ticket support roles, verify roles, reaction role templates, and giveaway host roles.

  • Feature toggles — on/off states and configuration values for scam detection rules, domain allowlists, phrase allowlists, ad-block settings, message counter status, audit log state, and reaction role template metadata.

2.2 User Data

  • User ID — numeric Discord identifier used across most features: message counting, premium subscriptions, gacha inventory, privacy preferences, verification state, ticket ownership, scam logs, command statistics, and giveaway entries.

  • Message counts — per-server integer count of messages sent. Only collected when a server administrator explicitly enables the message counter feature. Users may opt out individually.

  • Command usage — command name, user ID, and timestamp. Bot developers are excluded. Used for operational analytics visible only to developers via /stats.

  • Gacha data — roll count, virtual item inventory, email hash (when linked), and reset timestamps. Confined to the gacha system; has no real-world value.

  • Email addresses — collected when linking an email for account authentication or when a developer sends a premium code. Stored as SHA-256 hashes only. Plaintext email is never written to disk. Used solely for sending authorization codes or premium delivery.

  • Privacy preferences — per-user toggles for presence tracking, status visibility, and message counting. Honored immediately at runtime.

2.3 Premium Subscriptions

  • User ID, subscription tier (monthly / yearly / lifetime), redemption code, start date, and expiration date. Stored locally and in a remote PostgreSQL database. Used solely to verify premium status and enforce tier-based feature limits.

2.4 Ticket System

  • Channel and owner IDs — ticket channel IDs, owner user IDs, claimed-by user IDs, closure reasons, timestamps, and participant IDs.

  • Transcripts — full HTML transcripts of closed ticket channels, including message content, embeds, attachments, reactions, stickers, and system messages. Accessible only to ticket participants and authorized role holders.

  • Event history — lifecycle action log (opened, closed, reopened, claimed, members added/removed) with user IDs and timestamps.

2.5 Security & Moderation

  • Scam action logs — action ID, guild ID, author user ID, suspicious content snippet, matched pattern reasons, detected domains, and timestamp. Recorded when the scam shield detects or a moderator reviews content.

  • Scam feedback — moderator's user ID, pattern reasons, content, domains, and feedback label (true positive / false positive). Used to train the detection system's per-pattern confidence weights.

  • Pattern weights — per-detection-reason floating-point values (0.3–1.0) representing system confidence. No user-identifiable data.

  • Audit logs — Discord audit events (kicks, bans, role changes, channel modifications, message deletions, etc.) and @everyone/@here ping records, captured when enabled. Files auto-rotate at 20 MB.

2.6 Giveaways & Verification

  • Giveaway entries — participant user IDs, host user IDs, host role IDs, prize text, and timestamps.

  • Verification state — guild and user IDs of members currently completing captcha verification.

2.7 Automation

  • Auto-ping channel IDs and auto-role role IDs per guild. Used to send a temporary mention or assign a role when a member joins.

2.8 Gemini AI

  • Server IDs of guilds that have activated the Gemini playground. User prompts are sent to Google's Gemini API for processing and screened for policy violations before submission. Prompts and responses are not stored or logged by Equinox.

3. Data We Do NOT Collect

  • Presence, status, or activity data — member status (online / idle / dnd / offline), game activity names, Spotify data, and custom statuses are read from Discord's gateway in real-time to render command responses and immediately discarded. Never written to any database, file, or log.

  • Message content (outside documented features) — messages are scanned in memory for commands, scam detection, and syntax checking, then discarded. Content is only persisted when: (a) a message is flagged by the scam shield (snippet saved for moderator review), or (b) a ticket is closed (transcript saved for record-keeping).

  • IP addresses, browser fingerprints, device identifiers, or location data.

  • Data from users who have not interacted with the bot or who are not in a server where the bot is present.

  • Voice channel activity — the bot does not connect to voice channels.

  • Direct messages except those explicitly sent to invoke a command or receive an automated notification (scam warning, ticket transcript, verification timeout, reset notification).

4. How We Use Collected Data

  • Command execution — data is queried to fulfill slash commands (e.g., retrieving message counts for /messages count, checking premium for /premium, displaying inventory for /gacha inventory).

  • Feature configuration — administrator settings are persisted so the bot applies them consistently.

  • Security & moderation — real-time scam/phishing scanning, suspicious domain analysis, brand impersonation detection, Discord invite spam blocking. Moderator feedback trains the confidence model.

  • Audit logging — Discord audit events captured for server administrators to review moderation actions.

  • Analytics — anonymous command counts aggregated to monitor usage volume. No individual user's command history is exposed.

  • Premium management — verifying subscriptions, generating and redeeming codes, enforcing tier limits, and exporting codes for payment platforms.

  • Abuse prevention — command cooldowns, rate-limiting, join surge detection, and other protective measures.

5. Data Storage & Retention

5.1 Storage Locations

  • Primary database — SQLite (data/equinox.db) on the bot's host. Contains command stats, server configs, message counts, privacy settings, scam actions/feedback, verify configs, reaction role templates, ticket records, and giveaway data. Uses WAL mode with thread-safe locking.

  • Gacha database — separate SQLite (data/gacha.db) storing rolls, inventories, and email hashes. Uses in-memory write-through cache.

  • Premium database — remote PostgreSQL (Neon.tech) storing subscription records. SSL/TLS encrypted.

  • JSON files — premium code pools, user lists, and backup exports under data/. Retained for backward compatibility.

  • Audit logs — plain text under audit_logs/, one per guild. Auto-rotated at 20 MB.

  • Ticket transcripts — HTML files under ticket-json/transcripts/, one per closed ticket.

5.2 Retention Periods

  • Server configurations — retained while the bot is in the server. Removed on bot removal or administrator deletion.

  • Message counts — retained while the feature is enabled.

  • Ticket transcripts — retained until the ticket is deleted or the ticket system is removed.

  • Audit logs — retained indefinitely with auto-rotation. Administrators may request deletion.

  • Scam logs and feedback — retained indefinitely to maintain detection model accuracy.

  • Gacha data — retained until user triggers /account reset (24-hour cooldown, then permanent deletion).

  • Premium subscriptions — retained for the subscription duration plus a reasonable audit period.

  • Command stats — retained indefinitely for trend analysis.

  • Temporary data (message scans, presence/activity) — processed in memory and discarded immediately.

7. Data Security

  • Email hashing — all email addresses are SHA-256 hashed before storage. Plaintext is never written to disk.

  • Encryption in transit — PostgreSQL connections use SSL/TLS with channel binding. SMTP uses SSL (port 465).

  • Secrets isolation — API keys, tokens, and credentials are stored in environment variables and excluded from version control.

  • Database integrity — SQLite databases use WAL mode with thread-safe locking.

  • Feedback anti-abuse — scam feedback buttons are disabled after a single click and require Manage Server or Administrator permissions.

  • Transcript access control — transcripts are restricted to participants and authorized role holders.

8. User Rights & Controls

All controls are accessible via slash commands within Discord:

8.1 Opt-Out of Tracking

Use /activity privacy to independently toggle:

  • Presence Tracking — excludes you from /activity status, /activity games, /activity role, and /activity members.

  • Status & Activity — hides your status and activities from /userinfo.

  • Message Tracking — stops counting your messages. Your name still appears on the leaderboard with an opt-out indicator.

Changes take effect immediately and persist across sessions. Re-enable at any time.

8.2 Gacha Data Reset

Use /account reset to permanently delete all gacha data (rolls, items, linked email). A 24-hour cooldown is enforced. Deletion is irreversible.

8.3 Email Unlinking

Use /account unlink to remove your email hash from the database. Email verification is required before unlinking.

8.4 View Your Data

  • /account info — email linkage status, hash prefix, eligibility, roll count.

  • /premium — subscription tier and expiration date.

  • /gacha inventory and /gacha flex — inventory and stats.

  • /messages count — per-server message count.

8.5 Manual Removal

To request deletion of data not covered by self-service controls (scam logs, ticket transcripts, giveaway entries, audit logs), contact the team. See Section 10. Requests are processed within 14 business days.

9. Children's Privacy

Equinox is not directed at children under 13 (or the applicable digital consent age in their jurisdiction). NSFW commands are restricted to age-gated Discord channels.

Server administrators are responsible for ensuring compliance with Discord's age requirements. If we learn that personal data from an underage user has been collected without parental consent, we will remove it. Contact us immediately if you believe this has occurred.

11. Policy Updates

This policy may be updated as the bot evolves. The "Last updated" date reflects the most recent changes. Significant updates are announced in the support server. Continued use after an update constitutes acceptance.

12. Data Deletion Upon Bot Removal

When Equinox is removed from a server, new data collection stops immediately. Existing data is not automatically deleted — server owners may re-add the bot and expect configurations to persist.

A server administrator may request deletion of all server-associated data by contacting the team. Data is removed within 14 business days of a verified request.

13. Legal Basis (GDPR)

For users in the EEA and UK, Equinox processes personal data under:

  • Legitimate interest — processing server and user IDs is necessary to provide core bot functionality.

  • Consent — users voluntarily invoke commands and interact with features. Opt-out controls are provided for tracking features.

  • Contractual necessity — premium subscription data is processed to fulfill the purchased service.

EEA/UK users have rights to access, rectify, erase, restrict, and port their data. Contact the team to exercise these rights.
